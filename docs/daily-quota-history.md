# 每日额度折算（0.2.20）

在 Codex analytics 页点击 Codex Meter，摘要卡片下面新增“每日额度折算”。沿用最近 45 天范围，日期键统一按 UTC 展示，较新的日期在前。

表格列：日期、每日 Credits、每日消耗百分比、折算 100% 对应 Credits、推测周期及重置标记。计算使用未舍入的接口值：`Credits × 100 / 百分比`。Credits 显示三位小数，百分比显示六位小数；缺失、单位不匹配或分母为零时不推算。超过 100% 的历史消耗不截断。没有完整日数据的日期不伪造 Credits 为零；不展示获取时刻之后的日期。

## 重置记录

展开表格下方“记录全局重置（如 Tibo 重置）”，输入：

- Unix 秒时间戳，例如 `1788743391`；
- Unix 毫秒时间戳，例如 `1788743391000`；
- 带时区 ISO 时间，例如 `2026-09-07T09:09:51+08:00`。

不接受无时区时间和未来时间。保存后重新计算周期标记，重复时间不会重复保存。可删除单条记录。

记录存在 `chrome.storage.local` 的 `codexMeterGlobalResets` 中，按当前 account ID + user ID 隔离。刷新后保留；清空原来的用量快照不清除此记录。记录仅保存在本机，不会向 OpenAI 提交重置操作。

## 推测规则与限制

使用用户确认的口径：手动 `kind=used` 事件均作为周额度重置；领取事件不作为重置。手动/自记全局重置优先；有消耗的当前周窗口可作为推算锚点，0% 空闲窗口不作为固定锚点。其他日期按上个起点 +7天或此前累计百分比达到100%的次日提示可能重置。窗口起点未观测到时显示未知。

日内重置无法拆分当日用量。未知全局重置、日内跨周期、未完整返回的记录、空闲期间均可能导致周期推测不准，标记不参与每日折算。百分比接口可能按统一分母换算历史，折算值不能保证就是当时套餐的真实周额度上限。

新增两个只读接口：历史百分比和手动重置历史。任一个失败时保留原有用量报告并提示缺失。个人用量计数请求使用与官方个人分析一致的 `workspace_user=true`。原有美元折算系数未改动。
